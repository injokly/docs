# 웹 성능 개선 추진 현황 및 운영 측정 결과

## 1. 추진 배경

초기 진입 시 필요한 JavaScript와 정적 리소스의 전송·파싱·실행 비용을 줄이고, 로그인 성공 후 홈 주요 콘텐츠가 보이기까지의 전환 시간을 개선한다.

## 2. 개선 방향

| 개선 축 | 목표 |
| --- | --- |
| 초기 번들 경량화 | 초기 화면에 필요하지 않은 JavaScript의 다운로드·파싱·실행 비용 축소 |
| 정적 리소스 최적화 | 용량이 큰 애니메이션 리소스의 전송·디코딩 부담 축소 |
| 의존성/청크 구조 개선 | 공통 코드 중복을 줄이고, 특정 기능의 무거운 의존성을 필요 시점으로 분리 |
| 로그인 후 홈 전환 개선 | 로그인 성공 후 홈 주요 콘텐츠가 보이는 경로 및 측정 체계 개선 |

## 3. 적용 내역

| 항목 | 기존 상태 | 적용 내용 | 성능 영향 지점 | 상태 |
| --- | --- | --- | --- | --- |
| Eruda 제거 | 운영 환경의 초기 번들에 디버그 도구가 포함될 수 있음 | `eruda.js` 번들 제거 | JS 전송량·파싱·실행 | 적용 완료 |
| Lottie 경량화 | 초기 진입에서 애니메이션 에셋의 전송·디코딩 부담 발생 | Lottie 파일 크기 축소 | 정적 리소스 전송·디코딩 | 적용 완료 |
| UI 공통화 | UI 코드가 모듈별로 중복 포함될 가능성 | 공통 UI를 `packages/ui` shared로 통합 | 중복 JS 청크 | 적용 완료 |
| PDF 패키지 분리 | PDF 관련 의존성이 일반 화면 초기 로딩에 포함될 가능성 | PDF 기능을 `packages/pdfjs`로 분리 | 초기 번들 제외, 기능 진입 시 로드 | 적용 완료 |
| 로그인→홈 개선 | 로그인 성공 후 홈 전환과 성능 추적 기준이 분리되어 있지 않음 | preload 및 `onLoginSuccess` 기반 홈 전환·성능 추적 적용 | 로그인 성공 후 홈 주요 콘텐츠 노출 | 적용 완료 / 수집 중 |

## 4. 로그인→홈 성능 측정

로그인 성능은 앱 실행 전체 시간이 아니라, 로그인 성공 이후 홈 주요 콘텐츠가 화면에 표시되는 시간으로 측정한다.

```text
START: Perf.startPersistentTracking()
  → onLoginSuccess에서 홈 이동
FINISH: 홈 주요 콘텐츠가 화면에 표시된 시점
```

이벤트명은 다음을 사용한다.

```text
web-bootstrap-to-home-visible
```

Maxy 조회는 아래 기준으로 구분한다.

| 구분 | Custom 태그 value 조건 | runtime 조건 |
| --- | --- | --- |
| AS-IS | `"from":"/next/proxy-view"` | 이상, `1ms` |
| TO-BE | `"from":"/next/preload"` | 이상, `1ms` |

조회 경로:

```text
Maxy → 타겟분석 → Custom 태그
```

## 5. 운영 수집 결과

Maxy의 **타겟분석 → Custom 태그**에서 아래 조건으로 홈 로딩 성능을 수집한다.

| 구분 | 조회 조건 | 운영 수집 runtime | 비고 |
| --- | --- | ---: | --- |
| AS-IS | `"from":"/next/proxy-view"`, runtime ≥ 1ms | 평균 2.7초 (`n=300,000`) | 기존 홈 진입 경로 |
| TO-BE | `"from":"/next/preload"`, runtime ≥ 1ms | 평균 0.8초 (`n=70`) | 개선 홈 진입 경로 |

현재 Maxy에서는 평균값만 산출하고 있다. 10월 2일 패치를 통해 퍼센타일 기반 지표(P30, P50, P90)를 추가할 예정이다.

TO-BE runtime은 앱 실행 전체 시간이 아니다. `onLoginSuccess` 이후 홈 주요 콘텐츠가 화면에 표시될 때까지의 시간이다.

## 6. 효과 확인 방법

각 개선은 영향 지점이 다르므로 하나의 runtime 수치로 전체 효과를 판단하지 않는다.

| 개선 영역 | 확인 항목 | 확인 방법 | 현황 |
| --- | --- | --- | --- |
| 로그인 후 홈 전환 | 로그인 성공 후 홈 주요 콘텐츠 노출 시간 | Maxy Custom 태그의 AS-IS/TO-BE `from` 조건 조회 | 수집 중 |
| Eruda 제거 | 초기 번들에서 eruda 제외 여부 | 빌드 산출물 또는 Network 확인 | 확인 예정 |
| Lottie 경량화 | 에셋 파일 크기 변화 | 적용 전후 파일 크기 비교 | 확인 예정 |
| UI 공통화 | 중복 청크 감소 여부 | 빌드 산출물 분석 | 확인 예정 |
| PDF 분리 | 초기 진입 시 PDF 관련 청크 미로딩 여부 | 초기 화면 Network 확인 | 확인 예정 |

## 7. 보고 시 유의사항

- 적용 완료는 코드/번들 구조 변경이 반영되었다는 의미이며, 실제 사용자 체감 개선은 배포 후 데이터로 확인한다.
- 로그인→홈 Maxy runtime은 로그인 성공 이후부터 홈 주요 콘텐츠 노출까지의 범위다. 앱 실행부터 로그인 완료 전 과정 전체를 의미하지 않는다.
- PDF 분리는 일반 초기 진입의 부담을 줄이는 개선이며, PDF 기능을 처음 열 때의 로딩 비용이 없어지는 것은 아니다.
- UI 공통화의 실제 번들 절감량은 빌드 청크 구성 결과로 확인한다.

## 8. 결론

이번 개선은 초기 진입 경로에서 불필요하거나 무거운 리소스를 줄이고, 필요한 기능은 필요한 시점에 로드하도록 구조를 정리한 작업이다. 로그인 후 홈 전환은 Maxy 수집 데이터를 통해 배포 후 효과를 확인한다.
