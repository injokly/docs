웹 성능 개선 추진 현황 및 운영 측정 결과

초기 진입 리소스 비용을 줄이고 로그인 성공 후 홈 주요 콘텐츠 노출 경로를 개선한 작업 현황입니다.

1. 추진 배경

초기 진입 시 필요한 JavaScript와 정적 리소스의 전송·파싱·실행 비용을 줄이고, 로그인 성공 후 홈 주요 콘텐츠가 보이기까지의 전환 시간을 개선합니다.

2. 개선 방향

개선 축목표
초기 번들 경량화초기 화면에 필요하지 않은 JavaScript의 다운로드·파싱·실행 비용 축소
정적 리소스 최적화용량이 큰 애니메이션 리소스의 전송·디코딩 부담 축소
의존성/청크 구조 개선공통 코드 중복을 줄이고 무거운 의존성을 필요 시점으로 분리
로그인 후 홈 전환 개선로그인 성공 후 홈 주요 콘텐츠가 보이는 경로 및 측정 체계 개선

3. 적용 내역

항목기존 상태적용 내용성능 영향 지점상태
Eruda 제거초기 번들에 디버그 도구가 포함될 수 있음eruda.js 번들 제거JS 전송량·파싱·실행적용 완료
Lottie 경량화애니메이션 에셋의 전송·디코딩 부담Lottie 파일 크기 축소정적 리소스 전송·디코딩적용 완료
UI 공통화UI 코드의 모듈별 중복 가능성공통 UI를 packages/ui shared로 통합중복 JS 청크적용 완료
PDF 패키지 분리PDF 의존성이 일반 초기 로딩에 포함될 가능성PDF 기능을 packages/pdfjs로 분리초기 번들 제외, 기능 진입 시 로드적용 완료
로그인→홈 개선홈 전환과 성능 추적 기준이 분리되어 있지 않음preload 및 onLoginSuccess 기반 홈 전환·성능 추적로그인 성공 후 홈 주요 콘텐츠 노출적용 완료 / 수집 중

4. 로그인→홈 성능 측정

START: Perf.startPersistentTracking()
  → onLoginSuccess에서 홈 이동
FINISH: 홈 주요 콘텐츠가 화면에 표시된 시점

이벤트명: web-bootstrap-to-home-visible

구분Custom 태그 value 조건runtime 조건
AS-IS"from":"/next/proxy-view"이상, 1ms
TO-BE"from":"/next/preload"이상, 1ms

조회 경로: Maxy → 타겟분석 → Custom 태그

5. 운영 수집 결과

Maxy의 타겟분석 → Custom 태그에서 수집한 홈 로딩 runtime입니다.

구분조회 조건운영 수집 runtime비고
AS-IS"from":"/next/proxy-view", runtime ≥ 1ms평균 2.7초 (n=300,000)기존 홈 진입 경로
TO-BE"from":"/next/preload", runtime ≥ 1ms평균 0.8초 (n=70)개선 홈 진입 경로
현재 Maxy에서는 평균값만 산출하고 있습니다. 10월 2일 패치를 통해 퍼센타일 기반 지표(P30, P50, P90)를 추가할 예정입니다.

TO-BE runtime은 앱 실행 전체 시간이 아니라 onLoginSuccess 이후 홈 주요 콘텐츠가 화면에 표시될 때까지의 시간입니다.

6. 효과 확인 방법

개선 영역확인 항목확인 방법현황

Eruda 제거초기 번들에서 eruda 제외 여부빌드 산출물 또는 Network 확인확인 예정
Lottie 경량화에셋 파일 크기 변화적용 전후 파일 크기 비교확인 예정
UI 공통화중복 청크 감소 여부빌드 산출물 분석확인 예정
PDF 분리초기 진입 시 PDF 청크 미로딩 여부초기 화면 Network 확인확인 예정

7. 보고 시 유의사항

적용 완료는 코드·번들 구조 변경이 반영되었다는 의미입니다. 실제 사용자 체감 개선은 배포 후 데이터와 빌드/Network 결과로 확인합니다.
  • 로그인→홈 runtime은 로그인 성공 이후부터 홈 주요 콘텐츠 노출까지의 범위입니다.
  • PDF 분리는 일반 초기 진입의 부담을 줄이는 개선이며, PDF를 처음 열 때의 로딩 비용이 없어지는 것은 아닙니다.
  • UI 공통화의 실제 번들 절감량은 최종 청크 구성으로 확인합니다.

8. 결론

이번 개선은 초기 진입 경로에서 불필요하거나 무거운 리소스를 줄이고, 필요한 기능은 필요한 시점에 로드하도록 구조를 정리한 작업입니다. 로그인 후 홈 전환 효과는 Maxy 수집 데이터로 확인합니다.
